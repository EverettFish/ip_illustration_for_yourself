## ✨ What Is Mengli Style?

**Mengli (萌粒) = Meng (萌) + Li (粒).**

* **Meng:** cute/chibi proportions, simple facial features, relaxed and adorable.
* **Li:** the character feels like a tiny bean or particle, with plenty of breathing room instead of the dense, highly polished look of commercial illustration.

Typical characteristics include:

* Slightly naive, subtly shaky black pen lines;
* Natural pauses and small irregular gaps in the outlines while keeping the subject clearly readable;
* Clean color fills with slight white gaps or small edge misalignments allowed;
* Clear, normally saturated colors without applying a uniform gray wash or artificial vintage effect;
* Character identity takes priority over themed outfits, scene references, and layout references;
* Different assets use different composition scales instead of mechanically keeping the character the same size everywhere.

The goal is not to make something that looks “extremely polished because AI made it.”

It should feel more like a skilled illustrator casually developing a consistent personal visual language with a pen.

## 🧍 Step One Is Always the Character Anchor

The character reference answers one question:

**“Who is this character?”**

It does **not** determine the composition of every final asset.

The Skill locks:

* Overall hairstyle silhouette, bangs, side hair, and back-hair length;
* Face shape, eyes, skin tone, or fur color;
* Highly recognizable features such as hats, glasses, ears, or horns;
* Body proportions, common clothing, shoes, and accessories;
* Primary and secondary colors.

Later avatars, miniature characters, half-body reactions, back-view photo integrations, and themed outfits all reuse this identity lock.

Layout references only control **how things are arranged**. They must never replace your character with the person shown in a layout reference.

> A clear front-facing portrait plus one full-body image gives the most stable results. If an anchor has already been confirmed in the conversation, reuse it directly instead of recreating it.

## 🖼️ Article Illustrations and Reaction Packs Should Not Look the Same

Both use Mengli style, but they serve different purposes.

### Article Mini Illustrations: Idea First

* Understand the article first, then choose moments worth visualizing;
* A full character plus props usually occupies around **20–35%** of the canvas;
* The character is “performing an action,” and the scene supports the article's idea;
* Use more negative space and no text by default;
* Avoid mechanically repeating computers, light bulbs, robots, and stars.

### Reaction Packs: Reaction First

* Faces, gestures, and emotions must be instantly readable at chat-thumbnail size;
* The character and required props usually occupy around **45–70%** of the canvas;
* By default, **4–6 out of 12** reactions include a small, irregular contextual background, such as part of a desk, grass, a bed, clouds, or a windowsill;
* These mini scenes must not fill the entire canvas or become rectangular color cards. Clear white space should remain around them;
* The remaining reactions use a pure white background, giving the set variety while still making it feel like one cohesive series.

## 🎭 Reaction Pack Takeover: Replace the Whole Character, Not Just the Head

After the user uploads a specific reaction-image reference, the Skill first asks whether the entire set should use:

* The original reference artwork style;
* Mengli style;
* Or another specified style such as 3D or pixel art.

Once selected, the character, clothing, props, background, effects, and text presentation all follow the same unified visual style.

* Replace the **entire identity** of the original subject, including the head, body proportions, limbs, hands, feet, skin or fur, and species-specific characteristics;
* First distinguish the character's **body** from actual **clothing**. Fur color, belly, paws, ears, tail, and an animal's body must not be mistaken for clothing;
* If the original image contains actual clothing, preserve it and adapt it to the IP character's body. If there is no clothing, use the anchor's default outfit;
* Reproduce the reference composition at thumbnail-level geometry: character scale, crop, center of gravity, tilt, limb angles, hand placement, foot line, text blocks, and negative-space distribution should follow the original;
* Identity consistency does **not** mean returning the character to the anchor's standard pose. The IP character must fully perform the original reaction image's action, expression, and exaggerated deformation.

The repository includes three optional default references validated in a previous round: **Shh/End**, **Chubby Provocation**, and **OK/Stop**.

If the user has not uploaded a specific reaction reference, the Skill first asks whether they want to test a few of the default references.

If the user already uploaded their own references, the default assets are not mixed in automatically.

## 📷 Photo Integration: The Character Should Actually Enter the Scene

Photo integration uses the original photo as the editing base and directly produces the final integrated image.

The intended result is **not** “a transparent character layer pasted onto a photo.”

* The character must interact with a clearly identifiable object or surface in the photo — for example, leaning against a railing, sitting on steps, peeking from behind an exhibition stand, holding a door handle, pointing at a real sign, or observing an exhibit;
* The final image should include at least **two spatial-integration cues**, such as foreground occlusion, a real contact surface, contact shadows, reflections, perspective matching, or localized lighting/color matching;
* Preserve the original photo's dimensions, crop, camera angle, and overall composition. Only generate locally where required for the character interaction;
* Faces, products, text, architecture, exhibits, and other non-interactive areas of the photo must not be redrawn or altered;
* By default, the visible character height should occupy around **18–30%** of the final photo height, with **22–26%** preferred for ordinary scenes;
* Use **16–22%** only when intentionally depicting the character farther away, and the character should still remain recognizable without zooming;
* A fully visible character simply placed on top of the photo without occlusion or physical contact — looking like a floating sticker — is considered a failed result;
* Once this feature is triggered, the final integrated image must be displayed or attached directly in the response. Providing only prompts, a transparent character image, or a file path does not count as completion.

The goal is to make the IP character feel like it is **actually present in the scene**: its actions respond to the real environment, spatial relationships remain believable, and the important content of the original photo stays intact.

## 🧷 Three Default Sticker Sheets

When the user mentions “stickers,” “sticker sheet,” “die-cut stickers,” or `sticker sheet`, generate these three sets by default:

1. **Life Stickers:** food, drinks, rest, gaming, travel, and hobbies;
2. **Work Stickers:** coffee, computers, notes, meetings, and deadline crunches;
3. **Media Stickers:** shooting, editing, publishing, heart gestures, likes, and thanking supporters.

Each sheet uses a **3:4 light-colored background**.

At the top is a very light full-width themed illustration header. Below it are **10–20 individually die-cut stickers** arranged with varied spacing.

Large and medium stickers should primarily feature the IP character or an IP-centered scene. Standalone objects such as cameras, computers, or food should only serve as small decorative accents.

Stickers must not overlap. Their sizes should vary, while the overall composition remains balanced from left to right and from top to bottom.

Avoid piling all the small props along the bottom edge.

## 📁 Folder Icons: Four Distinct Concepts at a Time

By default, do **not** generate only one folder.

Also, do not simply recolor the same design four times.

The four concepts should vary in composition:

* The character peeks out from the top;
* The character sits or leans on the folder edge;
* The character appears from behind the front pocket while performing a small action;
* The character becomes part of a miniature themed scene on the front of the folder.

All four use the same **4:3 folder base template** and the same character anchor, while varying:

* Pose;
* Peek-out position;
* Silhouette direction;
* Folder color palette;
* One thematic prop.

Before final delivery, verify that the image contains a **real alpha channel**.

An image that merely *looks* like it has a checkerboard transparency background but is actually RGB is **not** a valid transparent deliverable.

### Changing a Folder Icon on macOS

1. Open the transparent PNG in **Preview**, then press `Command+A` and `Command+C`;
2. Select the folder in Finder and press `Command+I`;
3. Click the small folder icon in the upper-left corner of the Info window;
4. Press `Command+V`;
5. To restore the default icon, select the small icon again and press `Delete`.

For Windows, when explicitly requested by the user, center the transparent 4:3 image on a transparent 1:1 canvas and export it as an `.ico` file.

## 💌 Five Stationery Designs With Varied Character Placement

The five default themes remain:

* Spring;
* Love & Thanks;
* Summer;
* Winter;
* Chinese New Year.

However, the character should not appear only at the top of every page.

Across the set, rotate between:

* A horizontal scene at the top;
* A scene on the middle-right;
* A scene in the bottom-left;
* A horizontal scene at the bottom;
* A scene on the middle-left.

Each sheet should preserve around **58–70% writable space** and include **9–12 light hand-drawn horizontal lines**.

When the character appears on the side or bottom, shorten or offset the writing lines so they never pass through the character or major decorations.

## 🧩 Recommended Workflow

### STEP 01 | Upload a Character Reference

The reference can be:

* A real person;
* A pet;
* An original character;
* A toy;
* A robot;
* A company mascot;
* Or an existing animated character.

### STEP 02 | Confirm the Mengli-Style Anchor

First verify:

* Hairstyle;
* Face;
* Clothing;
* Accessories;
* Proportions.

Do not start batch generation until the anchor has been confirmed.

### STEP 03 | Choose One Feature or All-in-One

For example:

> Use this anchor to create 5 illustrations and 2 infographics for my article.

> Integrate this character into the three exhibition photos I uploaded.

> Create the complete All-in-One set, including stickers and folder icons.

### STEP 04 | Generate and Review Each Asset Type Separately

Each asset type has its own requirements for:

* Aspect ratio;
* Composition;
* Background;
* Transparency.

Keep images that have already passed review and regenerate only the failed items.

## ⚙️ How It Works in Codex

In Codex, whenever built-in image generation or editing tools are available, the Skill uses them directly.

It does **not** inspect, require, or restrict the name or version of the underlying image model.

For transparent assets, the Skill additionally verifies that the file contains a real alpha channel.

For photo integration, it checks that:

* The original image dimensions remain unchanged;
* Pixels outside the edited interaction region remain unchanged.

## 🙋 FAQ

### Can I use only one of the features?

Yes.

“All-in-One” means that all assets share the same anchor and visual-style system. You do **not** need to generate every asset type each time.

### Can I add references for articles, products, locations, or brands?

Yes.

Additional reference images control only the relevant content. They do not replace the character's identity or the Mengli style.

### Will text be added to images by default?

Article mini illustrations, avatars, and standard reactions do not include text by default.

Infographics require text.

Sticker sheets normally include only a short English series name in the header.

### Can multiple characters appear in the same set?

Yes.

Create an identity lock for each character first, then specify which assets should contain individual characters and which ones may contain multi-character scenes.

### Why verify the alpha channel for transparent images?

Because **drawing a checkerboard pattern is not the same as transparency**.

Folder icons and Polaroid-style frames count as valid transparent deliverables only when the actual file contains a transparency channel.
