# 🐟 萌粒风个人 IP 全套（All-in-one）

> **从一个确认过的形象锚点出发，生成一整套风格统一、身份稳定、可以长期复用的个人 IP 视觉资产。**

`ip_illustration_for_yourself` 不只是“把照片画成 Q 版”，也不只服务文章配图。

它会先把你的照片、宠物、原创角色、吉祥物或已有形象整理成一个稳定的 **萌粒风角色锚点**，后续的文章插图、信息图、实拍融合、贴纸、文件夹图标、信纸、拍立得边框、头像和表情包，都从这一个锚点继续生长。

```text
人物 / 宠物 / 角色参考图
          ↓
   萌粒风角色锚点
          ↓
文章插图 · 信息图 · 实拍融合 · 贴纸 · 文件夹图标
信纸 · 拍立得边框 · 场景头像 · 表情包 · 表情包夺舍
```

同一个发型、同一张脸、同一套标志性配色，在不同用途里仍然是“你”。这就是 All-in-one 的核心。

---

## ✨ 什么是萌粒风？

萌粒 = **萌** + **粒**。

- **萌**：Q 版比例、简单五官、松弛可爱；
- **粒**：角色像一颗小豆子，画面有呼吸感，不追求商业插画式的堆满和精修。

它的典型特征是：

- 稚拙、轻微抖动的黑色钢笔线；
- 轮廓有自然停顿和不规则小缺口，但主体依然清楚；
- 色块内部干净，边缘允许轻微露白或小幅错位；
- 颜色清晰、正常饱和，不统一蒙灰、不做旧；
- 角色身份高于主题服装、场景参考和版式参考；
- 不同资产使用不同构图尺度，不会机械地让人物永远一样大。

它不追求“AI 画得真精致”，更像一个很会画画的人，用钢笔随手留下的一套个人视觉语言。

## 🧍 第一步永远是角色锚点

角色参考图负责回答“这个人是谁”，而不是决定所有成品的构图。

Skill 会锁定：

- 发型外轮廓、刘海分区、侧发和后发长度；
- 脸型、眼睛、肤色或毛色；
- 帽子、眼镜、耳朵、角等高识别特征；
- 身体比例、常用服装、鞋子和配饰；
- 主色与辅助色。

后面的头像、微缩人物、半身表情、实拍背影和主题换装，都会重复这份身份锁。版式参考只控制“怎么排”，不能把角色换成参考图里的人。

> 一张清楚正脸 + 一张全身图最稳。如果对话里已经确认过锚点，后续直接复用，不重复重画。

---

## 🖼️ 文章小插画和表情包不会再长得一样

两者都保留萌粒风，但表达任务不同：

### 文章小插画：观点优先

- 先理解文章，再选择值得视觉化的节点；
- 完整人物与道具场景通常占画面约 20～35%；
- 角色是在“演一件事”，场景为文章观点服务；
- 留白更多，默认不加文字；
- 不机械地重复电脑、灯泡、机器人和星星。

### 表情包：反应优先

- 人脸、手势和情绪必须在聊天缩略图里一眼可读；
- 人物与必要道具通常占画面约 45～70%；
- 默认 12 张中有 4～6 张加入局部、不规则的小场景底，例如一小块桌面、草地、床铺、云朵或窗边；
- 小场景不能铺满画布，也不能做成矩形色卡，外围仍保留清楚的白色留白；
- 其余表情保持纯白底，整套有变化但仍然像一个系列。

## 🎭 表情包夺舍：完整换人，不只是换头

用户上传具体表情包参考图后，Skill 会先询问整组采用参考表情包原画风、萌粒画风，还是 3D、像素等其他指定画风。选定后，人物、服装、道具、背景、特效和文字呈现都统一到同一种画风。

- 替换的是原主体的完整身份，包括头、身体比例、四肢、手脚、皮肤或毛发和物种特征；
- 先区分“身体”和“真正穿在身上的衣服”：毛色、肚子、爪子、耳朵、尾巴和动物躯干不能误判成服装；
- 原图有真实衣服时保留并套到 IP 身体上；原图没有衣服时使用锚点默认穿搭；
- 构图执行缩略图级几何复刻：人物占比、裁切、重心、倾斜、肢体角度、双手落点、脚线、文字块和留白分布都跟随原图；
- 身份一致不等于站回锚点标准姿势。IP 身体必须完整表演原表情包的动作、神情和夸张变形。

仓库内附带上一轮验证过的 3 张可选默认参考：噤声/结束、肥嘟嘟挑衅、OK/打住。用户没有上传具体表情包时，Skill 会先询问是否从默认图里选择几张试生成；用户已上传参考图时，不会自动混入默认素材。

## 📷 实拍融合：角色要真正进入现场

实拍融合以原照片为编辑底图，直接生成最终融合成品，不用“透明人物层贴到照片上”作为最终结果：

- 角色必须与照片里一个明确对象或表面产生互动，例如靠着栏杆、坐在台阶上、从展台后探头、握住门把手、指向真实标牌或观察展品；
- 成品至少体现两项空间融合线索，例如前景遮挡、真实接触面、接触阴影、反射、透视匹配或局部光色匹配；
- 原照片的尺寸、裁切、视角和整体构图保持不变，只允许在角色互动区域做必要的局部生成；
- 照片里的脸、商品、文字、建筑和展品等非互动区域不能被重画或篡改；
- 默认让可见人物高度占最终照片高度的 **18～30%**，普通场景优先落在 **22～26%**；
- 只有刻意表现远景时才使用 16～22%，并且人物仍需不放大就能辨认；
- 完整角色平铺在照片上、没有遮挡或接触关系、像悬浮贴纸一样的结果会被判定为不合格；
- 功能启动后必须把最终融合成品图直接展示或附在回复中；只给提示词、透明人物图或文件路径不算完成。

目标是让 IP 真正进入现场：动作回应真实环境，前后关系可信，同时不破坏原照片的主体内容。

## 🧷 默认三张贴纸页

提到“贴纸”“贴纸页”“异形模切贴纸”或 `sticker sheet` 时，默认生成：

1. **Life Stickers**：吃喝、休息、游戏、出游和兴趣；
2. **Work Stickers**：咖啡、电脑、笔记、会议和赶工；
3. **Media Stickers**：拍摄、剪辑、发布、比心、点赞和感谢支持。

每张为 3:4 浅色底纸：上方是很浅的完整主题插图卡头，下方错落排布 10～20 枚独立模切贴纸。大、中贴纸都以 IP 或 IP 场景为核心；相机、电脑、食物等纯物件只做最小一级点缀。贴纸之间不重叠，大小有变化但整体左右齐、上中下均衡，不把小道具全部堆在底部。

## 📁 文件夹图标：一次给四个有趣方案

默认不是只生成一个文件夹，也不是同一张图换四个颜色。

四个方案会分别变化：

- 人物从顶部探出；
- 人物坐在或靠在文件夹边缘；
- 人物从前袋后面出现并做一个小动作；
- 人物融入文件夹正面的微型主题场景。

四张都使用统一的 4:3 文件夹母版和同一个角色锚点，但会改变姿势、探出位置、轮廓方向、文件夹配色和一个主题小道具。正式交付必须检查真实 Alpha；看起来像棋盘格但实际是 RGB 图片，不算透明成品。

### 在 macOS 更换文件夹图标

1. 用“预览”打开透明 PNG，按 `Command+A`、`Command+C`；
2. 在 Finder 选中文件夹，按 `Command+I`；
3. 点击简介窗口左上角的小文件夹图标；
4. 按 `Command+V`；
5. 恢复默认图标时，再次选中小图标并按 `Delete`。

Windows 版本会在用户明确需要时，把 4:3 透明图居中放进 1:1 透明画布并导出 `.ico`。

## 💌 五张信纸会混排人物位置

默认五个主题仍然是春天、爱心感谢、夏天、冬天和中国新年，但不会再把人物全部塞在页面上部。

整套会轮换使用：

- 顶部横向场景；
- 中部右侧场景；
- 左下角场景；
- 底部横向场景；
- 中部左侧场景。

每张保留约 58～70% 的可书写区域和 9～12 条浅色手绘横线。遇到侧边或下方人物时，横线会缩短或错开，不穿过人物和主要装饰。

## 🧩 推荐工作流

### STEP 01｜上传角色参考图

可以是真人、宠物、原创角色、玩偶、机器人、公司吉祥物或已有动漫形象。

### STEP 02｜确认萌粒风锚点

先检查发型、脸、服装、配饰和比例。锚点没确认，不批量往下做。

### STEP 03｜选择单项或 All-in-one

例如：

> 用这个锚点给文章做 5 张配图和 2 张信息图。

> 把这个角色融合进我上传的三张探展照片。

> 给我做完整 All-in-one，贴纸和文件夹都要。

### STEP 04｜分别生成并逐项验收

每种资产使用自己的画幅、构图、背景和透明要求。已通过的图片会保留，只修失败项。

## 🙋 常见问题

**可以只用其中一个功能吗？**

可以。All-in-one 指所有资产共享一个锚点和一套风格系统，不要求每次必须全部生成。

**能加入文章、产品、地点或品牌参考吗？**

可以。补充图片只控制对应内容，不会替代角色身份或萌粒风。

**默认会在图片里加文字吗？**

文章小插画、头像和普通表情默认不加字；信息图需要文字；贴纸默认只在卡头出现简短英文系列名。

**多个角色能放进同一套吗？**

可以。需要先分别建立身份锁，再明确哪些资产单人生成、哪些允许组合多人场景。

**透明图为什么还要验收 Alpha？**

因为“画出棋盘格”不等于透明。文件夹图标和拍立得边框只有在文件确实带透明通道时才算正式成品。
